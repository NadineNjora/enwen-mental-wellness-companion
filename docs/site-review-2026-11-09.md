# Student website review — 9 November 2026

## Changes delivered

- **Home:** hides the email address and removes the repeated saved-login and suggestion implementation notes. Personal welcome, consent status, next steps and trusted-person status remain.
- **Check-in:** warmer wording for student-life factors and the selection counter. The six-choice limit and submitted data are unchanged.
- **History:** one responsive area/line chart, one 10-point list and one 10-point average. Conversion is `recorded score / recorded maximum × 10`, so 4/5 displays as 8/10. The average normalises each entry before averaging. Original scores, denominators, dates and notes stay in the database. The backend retains original-scale summaries for API compatibility, but the student screen no longer shows two charts or the explanatory paragraphs. This mathematical display conversion is not a validated equivalence between clinical instruments.
- **Journal:** three new prompts bring the reflection choices to eight. Existing text is appended to, not overwritten. The mindful-minute activity remains unchanged.
- **Chat:** Nia is still the local Llama 3.2 model, not a different provider or clinical professional. The short versioned notice preserves private storage, AI limitations and separate contact permission. `/chat/screen` performs a fast, authenticated, transient rule check without inference, saving text or sending notifications. The UI shows support before waiting for the main chat/notification request. The main endpoint repeats the authoritative screen before any model call. Paused conversations stay paused and the composer is hidden. Added poison-related phrases and near-miss/negation tests. This remains a rule screen that can miss or over-flag language, not clinical risk prediction.
- **Reply preparation:** local generation is capped at 96 output tokens, the system prompt is shorter and requests keep the model loaded for 30 minutes. The system asks for concise replies. Hardware and model load still determine latency; this is not a response-time guarantee or streaming implementation. A minimal live service probe took 22 seconds for 32 output tokens on CPU; an earlier full-prompt probe failed during the deployment build, so instant replies are not claimed.
- **Community:** short sharing/review notices, per-reflection flower labels without displaying account identities, immediate navigation to My sharing after submission, and lookahead pagination that does not offer an empty extra page. Approved content enters the shared feed; pending content remains under My sharing. Another moderator must review the author's own submission. Checklist acknowledgement remains required. No existing submission was approved, declined or republished during this review.
- **Resources:** Library studio replaces Resource desk. This remains visible only to an approved curator; an ordinary student account was checked in the browser and did not see the entry. The editor explains adding a source and summary before publication. No AI drafting, article copying or publisher media embedding was added.
- **Campus sources:** seven public summaries were published through the curator workflow: UoN Wellness Centre, Strathmore Mental Health Club, USIU-Africa, KCA, KU Student Affairs, JKUAT and Tangaza's student association. Total: 21. Existing Daystar and Strathmore medical-centre sources remain. The Strathmore item is explicitly a past event; Tangaza's item is student-community information, not a promised clinical service. Prior resources and bookmarks were compared and preserved. Curator publication also updated the matching public knowledge summaries.
- **Contact page:** one email invitation journey replaces the duplicate Mailpit/student forms. Saved details prefill without overwriting edits. Short notices, a flower confirmation dialog, and accurate invitation/permission states replace repeated technical wording. A per-account capability check identifies laptop restrictions before submitting. Brevo remains the real provider. - **Safety emails:** the subject requests support for the student's trusted person and the message asks for a caring direct check-in. No raw messages, notes or scores are included. The screen reports submission honestly and never promises that an email was read or a person will respond. Previous provider receipts in saved history receive concise, truthful display wording.

## Separately approved signup invitation

The first broad registration/email change was rejected by automatic approval review. The user then explicitly approved a narrower implementation: an **unticked, separate signup choice**, no changes to existing accounts, an OFF-by-default laptop switch and fake-only tests.

The new `signup_invitation_choices` table records the exact notice and nominated recipient, a stable request identifier and the attempted outcome. `SIGNUP_CONTACT_INVITATIONS_ENABLED` defaults to false. Automatic signup sending additionally requires production delivery mode, public HTTPS and the configured verified Brevo sender. It never runs in local-demo mode. A changed recipient or stale choice cannot inherit the permission. Recipient acceptance and the student's separate safety-email permission are still required for later contact alerts.

Account creation commits before any invitation attempt. A sending failure does not delete the account. A repeated signup or dispatch does not resend. Uncertain attempts are not automatically retried. Cross-account requests to the same recipient are capped at three invitations per 24 hours. New choice storage is additive; historical accounts, consents and contacts were not converted or enrolled. The current laptop's delivery environment was not edited.
